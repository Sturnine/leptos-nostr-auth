# leptos-nostr-auth

## Project management

CCPM PRDs, epics and tasks in `.claude/` stay local. Never sync them to GitHub: no epic sync, no
`gh issue` create, comment or close for ccpm work, and `github:` frontmatter stays empty. Rollouts
close tasks by updating the local files. The repo is public and these files describe unfixed bugs.

## Releases

`main` is the only long-lived branch. Changes land through PRs into `main`, which the ruleset gates on the CI checks and merge commits only.

The ruleset requires a PR branch to be up to date with `main`. Actions run only if pinned to a full commit SHA and listed in the repo's allowed actions (Settings, Actions), which must include every action a new action calls. Release tags `v*` cannot be moved or deleted.

A release starts when the maintainer runs the `Release PR` workflow on `main` with a version. It runs `scripts/prepare-release.sh`, which bumps `Cargo.toml` and every lockfile and inserts a changelog section generated by git-cliff (`cliff.toml`) from Conventional Commits, and opens a `release-vX.Y.Z` PR. Keep that PR to its one commit. On every push to `main`, the `Release` workflow looks for a `Cargo.toml` version with no `v` tag yet. When it finds one, it runs cargo-semver-checks against crates.io, publishes the pushed commit through trusted publishing in the `release` environment, and creates the `vX.Y.Z` tag and GitHub release on that commit. Merging any PR that bumps the version releases it.

Agents never run the release workflows, merge a release PR, push a `v*` tag, push to `main`, publish, or edit `CHANGELOG.md` entries for released versions. Commit subjects become changelog lines: write them for readers of the release notes. `chore`, `ci`, `test`, `style` and `build` subjects are left out.
